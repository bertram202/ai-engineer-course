# Проект M01. Уверена ли модель, когда права?

## Задача

Модель отвечает одинаково гладко и когда знает ответ, и когда ошибается. Но в её вероятностях
остаётся след сомнений. Проверьте, можно ли по `logprobs` отличить правильные ответы
от неправильных и какая из двух моделей курса лучше «знает, чего не знает».

Набор вопросов — `questions.jsonl`: 30 вопросов с однозначными ответами. Среди них факты,
арифметика и задачи на буквы, в которых LLM часто ошибаются из-за токенизации.

## Требования

1. Напишите `project/confidence.py`. Для каждого вопроса и каждой модели (`main` и `local`):
   - получите короткий ответ с `logprobs=True` и выключенными рассуждениями (`extra_body=no_thinking()`),
     попросив модель отвечать одним словом или числом;
   - проверьте правильность: ответ после нормализации (нижний регистр, `ё` → `е`, без знаков препинания)
     содержит один из вариантов из поля `answers`; числа сравнивайте как отдельные слова;
   - посчитайте две меры уверенности: вероятность первого токена ответа
     и среднюю вероятность токена $\exp(\overline{\log p})$ = 1 / перплексия.
2. Сохраните результаты в `project/results.csv`: вопрос, модель, ответ, верно ли, обе меры уверенности.
3. Постройте для каждой модели:
   - точность (доля верных ответов);
   - средние меры уверенности отдельно для верных и неверных ответов;
   - график «уверенность → доля верных»: разбейте ответы на 3–4 группы по уверенности.
4. Напишите в `project/results.md` 5–10 предложений: на каких вопросах модели ошибаются,
   бывают ли они уверенно неправы, какая мера уверенности полезнее и почему.

## Критерии оценки

| Критерий | Баллы |
|---|---|
| Код запускается `uv run python project/confidence.py`, запросы идут через `mlcourse` | 2 |
| Проверка ответов корректна: нормализация, числа как отдельные слова | 2 |
| Обе меры уверенности посчитаны правильно | 2 |
| Графики и таблица по двум моделям | 2 |
| Выводы опираются на цифры, а не на впечатления | 2 |

## Подсказки

- Ответы кэшируются в `~/.cache/mlcourse/llm`: повторный запуск скрипта не ходит в модель.
- Если модель отвечает длинно, добавьте в системный промпт «Отвечай одним словом или числом, без пояснений»
  и ограничьте `max_tokens`.
- Высокая уверенность в неверном ответе — главный риск LLM в продакшне. Как это измеряют
  системно (калибровка, ECE), разберём в M02 и M22.

## Как сдать

Закоммитьте `confidence.py`, `results.csv` и `results.md` в свою ветку и откройте pull request
в свой форк курса. Проверить себя можно с агентом-репетитором: `make opencode`, затем попросите
его отревьюить проект (агент `reviewer`).
