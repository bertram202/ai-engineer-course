# Проект M02. Детектор негативных отзывов

## Задача

Маркетплейс хочет автоматически находить негативные отзывы и отправлять их в поддержку.
Пропущенный негатив дорог: недовольный клиент уходит. Лишний отзыв в очереди поддержки стоит
несколько минут работы оператора. Требование бизнеса: **находить не меньше 90% негативных отзывов**
при как можно меньшем числе ложных срабатываний.

Данные — RuReviews (`mlcourse.fetch("rureviews")`): класс `negative` против остальных.

## Требования

1. **Гигиена данных.** Уберите из теста отзывы, которые после нормализации совпадают с отзывами
   из train (урок 4). Сколько их было?
2. **Модели.** Сравните кросс-валидацией на train минимум две модели в `Pipeline`, например
   TF-IDF (слова и/или символьные n-граммы) + логистическая регрессия и TF-IDF + линейный SVM
   или бустинг. Метрики — ROC-AUC и PR-AUC со средним и стандартным отклонением по фолдам.
3. **Порог.** По предсказаниям кросс-валидации (`cross_val_predict`) выберите порог, дающий
   recall ≥ 0,9. Порог выбирается только на train.
4. **Калибровка.** Постройте калибровочную кривую, посчитайте Brier score. Если калибровка плохая,
   исправьте её (`CalibratedClassifierCV`) и покажите результат.
5. **Финальная оценка.** Один раз на очищенном тесте: recall и precision при выбранном пороге
   с 95% доверительными интервалами бутстрепом (1000 повторов выборки теста с возвращением).
6. **Анализ ошибок.** 15 самых уверенных ошибок модели: что в них общего? Есть ли среди них
   ошибки разметки (см. противоречивые метки в уроке 4)?
7. **Отчёт** `project/report.md`: таблица моделей, выбранный порог, итоговые метрики с интервалами,
   выводы из анализа ошибок, одна рекомендация бизнесу.

## Критерии оценки

| Критерий | Баллы |
|---|---|
| Нет утечек: всё обучаемое — в `Pipeline`, порог и калибровка — только по train, тест очищен | 3 |
| Корректное сравнение моделей кросс-валидацией | 2 |
| Порог обеспечивает recall ≥ 0,9 на тесте (с учётом интервала) | 2 |
| Бутстреп-интервалы посчитаны верно | 1 |
| Анализ ошибок и выводы опираются на примеры и цифры | 2 |

## Подсказки

- Бутстреп: `idx = rng.integers(0, n, size=n)`, метрика на `y[idx]`, повторить 1000 раз,
  интервал — 2,5-й и 97,5-й перцентили. Подробно доверительные интервалы для оценки LLM-систем
  разберём в M22.
- Символьные n-граммы (`analyzer="char_wb", ngram_range=(2, 5)`) устойчивы к опечаткам,
  которых в отзывах много.
- В M04 эту же задачу решат дообученный BERT и LLM без обучения. Сохраните свои цифры для сравнения.
